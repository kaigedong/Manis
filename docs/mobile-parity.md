# 移动端功能对照与重设计

桌面版是功能基线，Android 只做「能带走的那部分」。这份文档记录两边的差距，以及移动端为什么这样组织。

## 桌面端功能清单

| 领域 | 桌面能力 | 移动端现状 | 结论 |
| --- | --- | --- | --- |
| 订阅 | 多订阅源、启停、用量/到期展示、QX 规则列表来源、订阅预览 | 多订阅源、启停、刷新 | 保留；预览暂不做 |
| 节点 | 订阅节点 + 手动 VLESS 节点、延迟测试、按组选最快 | 已对齐 | 完成 |
| 策略组 | 手动 / 延迟优选 / 故障转移 / 负载均衡、名称匹配、Proxy 动态出口、毫秒余量 | 手动 / 自动测速、订阅与节点成员 | 缺故障转移、负载均衡、名称匹配 |
| 规则 | 手动规则 + 多个 QX 规则来源（URL 订阅、缓存、刷新） | 仅手动规则文本 | 缺规则来源 |
| 路由 | 直连 / 全局 / 规则 | 已对齐 | 完成 |
| 出口 IP | 逐节点探测出口 IP | 无 | 缺 |
| 网络活动 | 实时连接、路由证据、一键建规则 | 仅内核日志 | 缺 |
| 系统集成 | 系统代理、TUN、登录自启、单实例 | VpnService 接管全机 | 平台差异，无需对齐 |
| 配置 | 可读配置编辑（JSONC）、完整备份导出/导入、自动备份 | 剪贴板备份/恢复、内核日志 | 缺文件导入导出 |
| 节点 DNS | 每订阅 `proxy-dns`、订阅文档自动发现 | 自定义 DoH + 自动发现 | 完成 |

## 移动端信息结构

底部五个页签，按「用的时候在想什么」划分，而不是按数据类型：

| 页签 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| 连接 | 现在通不通、走哪里 | 开关、当前出口、路由模式、整组不可达提示 |
| 节点 | 有哪些出口、哪个快 | 策略组 → 节点，延迟、当前标记、选最快 |
| 订阅 | 出口从哪来 | 订阅源、手动节点、策略组定义、刷新 |
| 规则 | 流量怎么分 | QX 风格规则、策略指向校验 |
| 设置 | 排障与迁移 | 连接信息、配置摘要、节点域名解析、备份与恢复、诊断 |

设计原则与桌面一致：**先给事实，再给操作**。每页顶部是一条状态摘要，下面是操作；不做隐藏手势，不叠弹窗。

## 下一步（按价值排序）

1. 规则来源：把 QX 规则列表做成可增删的来源，与桌面同一套解析。
2. 出口 IP：复用桌面隐藏探针组 + 回环 listener。
3. 策略组补故障转移 / 负载均衡 / 名称匹配。
4. 文件级备份：`ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT` 取代剪贴板。
5. 网络活动：从 controller `/connections` 拉取并展示路由证据。
